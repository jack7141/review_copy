## 제품 기획서

### 1. 제품 정의

**한 문장**: 후기 20개를 붙여넣으면, 랜딩/광고/FAQ/DM 세트를 '근거(후기 #n)'까지 달아서 즉시 쓰게 만들어주는 매출 문서 생성기.

**핵심 고객**: 후기가 이미 쌓여있는 업종 — 강사·코치 / 학원 / 시술·예약업 / B2B 에이전시 / SaaS

**공통 문제**: "후기는 있는데 매출 문서(랜딩·광고·세일즈)로 못 바꿈"

---

### 2. GPT 대비 핵심 차별점 6가지

> GPT는 **"카피를 써주는 도구"**, 우리는 **"쓰게 되는 문서 시스템"**

| # | 차별점 | 설명 |
|---|--------|------|
| 1 | **Evidence 강제** | 모든 문장에 근거 후기 번호 `[근거: #3, #11]` 필수 → "그럴싸한데 불안" 해소 |
| 2 | **채널 규격 고정** | Ads 헤드라인 20개(길이제한), Landing 8블록, DM 5개 등 고정 → 매번 형식이 바뀌지 않음 |
| 3 | **리스크 가드레일** | 과장/확정/비교우위/민감업종 표현 자동 경고 + 대체 문구 제안 |
| 4 | **후기→포인트 추출→문서 변환 파이프라인** | 반복 포인트/반박/USP 먼저 추출 → "전환용 구조"로 생성 |
| 5 | **브랜드 톤/금칙어 프리셋** | 매번 설명 없이 동일 톤 출력 |
| 6 | **UX(한 번에 끝)** | 붙여넣기 → 생성 → 복사까지 1화면 |

---

### 3. MVP 스코프

**포함**: 입력 폼 + 결과 4탭 + 근거 표시 + 복사 버튼 + 기본 가드레일

**제외(절대 금지)**: 로그인 / 팀 / 결제 / 저장 / 연동 / 랭킹 / 리뷰 시스템 / 한국 플랫폼 직접 연동
→ "돈 된다" 확인 후에만 추가

---

### 4. 사용자 흐름 (UX)

| 페이지 | 역할 |
|--------|------|
| `/` | 랜딩: 문제 / 데모 / CTA |
| `/app` | 생성기: 입력 → 결과 |
| `/privacy`, `/terms` | 간단 정책 |

**`/app` 화면 구성**:

```
┌─────────────────────┬──────────────────────────────┐

│ · 제품/서비스명       │  [Landing] [Ads] [FAQ] [DM]  │

```

### 5. 출력 템플릿 (고정 규격)

#### Landing (8블록 고정)
1. 헤드라인 (누구/무슨 결과)
2. 문제 공감
3. 해결 약속
4. USP 3~5개 (+근거)
5. 사용 방법/구성
6. 후기 하이라이트 3~5개
7. FAQ 8~12개 (업종별)
8. CTA (다음 행동)

#### Ads
- 헤드라인 20개 (길이 제한)
- 배너 문구 10개 (7~12자)
- 짧은 본문 10개 (채널별 톤 옵션)

#### FAQ
- 질문 10개 (구매 저항 중심)
- 답변은 "확정"이 아닌 "근거 기반" 표현 우선

#### DM/Sales
- 문의 유도 DM 5개 (짧게)
- 상담 스크립트 1개 (오프닝→진단질문→제안→마무리)

### 6. 기술 설계

**API**: `POST /api/generate` (또는 Server Action)
- 입력 검증 (길이 제한/빈값/금칙어)
- LLM 호출 → JSON 스키마 강제 → 프론트 렌더링

**Evidence 매핑 (가장 중요)**:
- 후기 `#1..#N` 번호 부여
- 모델에 "모든 문장에 evidence 배열(후기 번호) 반드시 포함" 강제
- 후기 문장 일부 짧은 인용 → 추후 "근거 미리보기" 확장 가능

**비용/남용 방지 (최소)**:
- 비로그인 MVP: IP/쿠키 기준 일일 제한 (3회)
- 입력 글자 수 제한 (후기 총합 8,000~15,000자)
- 저장 기본 OFF (개인정보 우려 최소화)

---

### 7. LLM 프롬프트 설계

**시스템 원칙**:
- 사실처럼 보이는 새로운 주장 금지
- 모든 문장에 evidence 최소 1개
- 과장/확정 표현 제한 ("무조건/완벽/100%")
- 업종별 위험 문구 경고 (warnings 배열로 반환)

**출력은 JSON만** → 프론트에서 바로 렌더링할 수 있게 스키마 고정

---

### 8. 검증→출시 전략

**검증 (개발 전)**:
- 데모 영상 45~60초 먼저 제작
- CTA: "베타 10명 (무료/할인)"
- 체크 지표: 요청 수 / 베타 신청 수 / 유료 의사

**유통**:
- Threads: 전/후 예시 1개
- 니치 커뮤니티: 코치/학원/예약업 대상 샘플 문서 공유
- 기존 트래픽 교차 유입

---

### 9. 수익화

**초반**: 1회 구매(팩)
- Starter (1회): Ads + FAQ
- Pro (1회): Landing + Ads + FAQ + DM

**이후**: 월 N회 생성 + 브랜드 프리셋 저장 구독 모델
